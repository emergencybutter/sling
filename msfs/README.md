# Sling TSi for Microsoft Flight Simulator 2024

A flyable MSFS 2024 aircraft built from the 3D model in `../model` (POH 3-view geometry).

**Picking this up?** Read [docs/MSFS2024_DEV_NOTES.md](docs/MSFS2024_DEV_NOTES.md) first. It covers everything learned about
MSFS 2024 development on this project, including the build pitfalls and the autopilot/vacuum debugging.

## Build

```
python tools/build.py            # export the 4 LODs, textures, configs and thumbnails
python tools/build.py --package  # ... then compile with the SDK's fspackagetool and refresh layout.json
```

`--package` runs `MSFSLayoutGenerator.exe .\layout.json` in the compiled package folder. It expects the
tool at `C:\Users\arnau\Downloads\MSFSLayoutGenerator.exe`, or wherever `MSFS_LAYOUT_GENERATOR` points.
MSFS must be closed while packaging.

This needs Blender 5.x and the MSFS 2024 SDK at their default paths. You can point elsewhere with
the `BLENDER` and `MSFS2024_SDK` environment variables. The compiled package lands in
`Packages/arnaud-aircraft-sling-tsi`. To install it, copy that folder into your `Community` folder.

You can also open `SlingTSiProject.xml` in the sim's Developer Mode (Project Editor) and build it there.

## Pipeline

1. `tools/blender_export.py` runs inside Blender. It adds spin nodes for the tyres and splits the
   propeller into blades and a blur disc. It names the light and screen meshes, moves the origin to
   the reference datum (root quarter chord), turns the model to MSFS axes and exports glTF. It also
   writes each hinge axis to `meta.json`.
2. `tools/postprocess_gltf.py` removes extensions the sim doesn't read and turns the screens into
   emissive render targets. It then appends the 13 keyframed animations that `common/model/SlingTSi.xml` drives.
3. `tools/make_configs.py` writes `flight_model.cfg`, `engines.cfg` and `cameras.cfg`. It takes the
   SDK sample's layout and tables and sets the Sling's values. Positions are in feet from the datum.

All of `common/model`, `common/texture` and the three generated `.cfg` files get overwritten by
`build.py`. Edit the scripts, not the outputs.

## Autopilot notes

The GFC 500 autopilot is flown by the Working Title G3X Touch and has been checked with `tools/ap_monitor.py` (HDG turns both ways, ALT capture). Two settings are essential:

- **`[AUTOPILOT]` in `systems.cfg`** is the default NX Cub's. It uses `use_no_default_bank/pitch = 1` together with the full set of roll, pitch, heading, VS, FLC and nav PID gains and `pitch_use_elevator_only = 1`. Without the gains the servos don't move.
- **`[VACUUM_SYSTEM]` must work** even though the real Sling has no vacuum pump. The G3X reads the sim's gyro instruments, which topple without vacuum. That shows up as a tilted horizon line on the G3X and an autopilot steering the wrong way.

`python tools/ap_monitor.py SECONDS` logs the whole chain live over SimConnect (`pip install SimConnect`): attitude, gyro instruments, suction, AP modes, bank/pitch hold refs and control positions.

## Not yet verified in the sim

Verified so far: the G3X Touch boots and shows the Rotax engine page, the attachment instruments sit flush,
the control surfaces move correctly under manual control, and the autopilot flies HDG and ALT. Still open:

- **Flight model tuning.** Speeds, power and drag come from published figures, and the flight model now runs
  modern-only with the NX Cub's modern keys, but the performance hasn't been checked. Check the stall speeds
  (47/56 KIAS), the 135 KTAS cruise and the climb (roughly 1,000 fpm). Then adjust `[FLIGHT_TUNING]` /
  `parasite_drag_scalar` in `flight_model.cfg` and `power_scalar` / `max_design_mp` in `engines.cfg`.
- **Autopilot modes beyond HDG and ALT.** NAV, VS, FLC and approach haven't been flown yet.
- **G5.** Back on after the vacuum fix; check that its attitude and flight director agree with the G3X.
- **Cockpit animations.** The sticks, pedals, throttle, brake lever and flap knob should follow the controls;
  if one moves the wrong way, flip its keys in `postprocess_gltf.py`.
- **Doors.** They are interactive points 0 (left) and 1 (right) in `flight_model.cfg`. Clicking the latch lever at the bottom centre of each door should open or close it, and the door and its lining swing up about 80 degrees in about 3 s.
- **Cockpit switches.** The switches, knobs and buttons are modelled from the POH but aren't clickable yet.
  Use the sim's controls and the G3X touch screen.
